## Purpose

Structured-data emission per page type. Schema.org JSON-LD is the canonical form (Google's recommended format). Per-type templates: **Article** (blog posts), **Product** (e-commerce), **Organisation** (homepage), **FAQPage** (Q&A pages), **HowTo** (tutorials), **LocalBusiness** (brick-and-mortar), **BreadcrumbList** (navigation), **Person** (author bios).

Framework-aware: emit pattern differs per stack (Next.js `generateMetadata` / Astro `<head>` / SvelteKit `+page.ts` / Nuxt `useHead` / WordPress filter / vanilla `<script type="application/ld+json">`). Reads `tech-stack.md` to pick the right scaffold.

## When to Use (Proactive Triggers)

1. Phase 8 implementation — per-page-type schema injection scaffolding
2. New page type added — add schema template
3. User says "JSON-LD" / "schema markup" / "Open Graph" / "rich results"
4. Pre-deploy gate — verify schema validates against schema.org grammar

## Output Artifacts

1. **JSON-LD schema definitions** per page type at `_context/implementation/seo-schemas/<type>-schema-v{N}.json`
2. **Framework scaffolds** — emitted into the project's source tree (e.g., `app/components/Schema.tsx` for Next.js, `src/components/Schema.astro` for Astro)
3. **Open Graph + Twitter Card templates** at `_context/implementation/seo-schemas/social-meta-v{N}.md` — title/description/image-aspect-ratio guidance per page type
4. **Validation report** — runs `https://validator.schema.org/` (or `npx schema-dts-validator`) on emitted schemas; flags malformed structures

## Prerequisites

- Phase 3 tech-stack locked
- Phase 5 seo-content content briefs (informs which page types exist)
- Framework supports server-side rendering OR build-time HTML emit (CSR-only fails for crawlers)

## Process

1. **Read tech-stack.md** to determine framework + emit pattern
2. **Per page type identified in content strategy:**
   - Author canonical JSON-LD template (schema.org compliant)
   - Map to framework's metadata API (e.g., Next.js `generateMetadata` returns `metadata.other['ld+json'] = JSON.stringify(...)`)
   - Author Open Graph + Twitter Card meta-tag set
3. **Emit framework scaffolds** into project source tree (annotated with `// SEO-SCHEMA: generated by coldpress-os seo-schema skill v1.0` for traceability)
4. **Validate** — schema.org structure check; flag missing required properties (e.g., Article needs `headline` + `datePublished` + `author`)
5. **Emit definitions + validation report**

## Activation-Gate Checklist

- [ ] tech-stack.md identifies framework + emit pattern
- [ ] At least one schema type emitted (BreadcrumbList minimum for any multi-page site)
- [ ] Framework scaffolds compile (TypeScript / linter pass)
- [ ] Open Graph image aspect ratio matches social platform requirements (1.91:1 for OG; 16:9 for Twitter)
- [ ] schema.org validation: zero ERRORs (warnings acceptable with rationale)

## Output

JSON-LD definitions + framework scaffolds + validation report. Phase 9 deploy gate verifies schema validates.

## Page-type → schema cheat sheet

| Page | Required schema | Optional supplemental |
|---|---|---|
| Homepage | Organisation + WebSite | LocalBusiness (if local) |
| Blog post | Article | Person (author), BreadcrumbList |
| Product page | Product + Offer | Review, AggregateRating |
| FAQ page | FAQPage | BreadcrumbList |
| Tutorial | HowTo | VideoObject (if video) |
| Local landing | LocalBusiness | OpeningHoursSpecification, GeoCoordinates |
