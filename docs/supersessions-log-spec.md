# Supersessions Log — Format Specification

When Phase 2 (or later-phase) discovery contradicts material in `_input/`, Butler invokes `promptSupersede` (`src/governance/supersede.ts`). On user confirmation, the helper appends a row to the day's supersessions log in `_context/audit/`.

---

## File location

```
_context/audit/supersessions-{YYYY-MM-DD}.md
```

One file per calendar day. If no supersessions occur on a given day, no file is created.

## Table structure

```markdown
# Supersessions Log — {YYYY-MM-DD}

| Entry ID | Date | Sacred Doc | Superseded _input/ | Rationale | Context |
|---|---|---|---|---|---|
| sup-20260424-_input-reference-old-brief | 2026-04-24 | _context/sacred/context.md | _input/reference/old-brief.md | User confirmed SMB pivot after discovery interview | pre-project-interview Step 1 — vision question |
```

### Column definitions

| Column | Content |
|---|---|
| **Entry ID** | `sup-{YYYYMMDD}-{slug}` — unique per row; generated by the helper from date + last 32 chars of the `_input/` path. |
| **Date** | ISO date of the decision. |
| **Sacred Doc** | Relative path to the sacred doc that now supersedes the input. |
| **Superseded _input/** | Relative path to the `_input/` file whose conclusions are no longer authoritative. |
| **Rationale** | Free-text from the user (or `decisionContext` if user gave no explicit rationale). |
| **Context** | The `decisionContext` string from the calling skill step — names the step and the specific conflict that triggered the check. |

## Append-only contract

- **Never delete or edit rows.** If a supersession decision is reversed (rare), add a new row with a "reversal" rationale pointing back to the original Entry ID.
- **Pipe characters** in rationale or context text are escaped as `\|` by the helper.
- **Multiple rows per day** are appended sequentially. The header and column row are written once when the file is first created.

## Graph edge relationship

Every confirmed supersession also writes a `superseded_by` edge in `.coldpress/graph/graph.json`:

```json
{
  "source": "_input/reference/old-brief.md",
  "target": "_context/sacred/context.md",
  "relation": "superseded_by",
  "confidence": "MANUAL"
}
```

The `MANUAL` confidence signals to Graphify that this edge was written by the governance layer and should be preserved across graph rebuilds (Graphify v2 merge semantics — see Graphify docs).

## When to consult this log

- **Phase gate checks**: Phase 2 gate evaluates `supersessions-log-if-applicable` — warns if `_input/` files are referenced in gate artefacts but no supersession log row explains the divergence.
- **PRD authoring**: Phase 4 `create-prd` checks the supersessions log to ensure known conflicts are acknowledged before requirements are locked.
- **Audits**: `repo-structure-audit` includes a stale-supersession check — flags `_input/` files with a `superseded_by` edge that the project lead has not marked as `archived`.
