## Purpose

Make the styleguide **load-bearing**, not merely asserted. A story's UI must use
the design tokens; this skill catches divergence — a wrong font, an off-palette
color, a 14px where the scale says 16px — mechanically. Part of the verifier's
pass (the verifier is read-only; this only reads + runs checks).

## Process

1. **Render + extract** — with Playwright, load the story's components (on the
   preview URL, and the matching section of the `/styleguide` route). Extract the
   **computed styles** actually used: `color`, `background-color`, `font-family`,
   `font-size`, and margins/paddings. Write them to
   `_context/design/used-styles.json`:

   ```json
   { "colors": ["#3b82f6", "#111827"], "fontFamilies": ["Inter, system-ui"],
     "fontSizes": ["1rem", "24px"], "spacings": ["4px", "8px"] }
   ```

2. **Token check** — run:

   ```bash
   coldpress visual-verify
   ```

   It fails (exit 1) on every value that is not a token: an off-palette color, a
   non-token font family, a font size outside the type scale, an off-scale spacing.
   Fix by using `var(--…)` from `tokens.css` (generated by `coldpress tokens build`).

3. **Baseline diff** — screenshot the story's components per breakpoint (light +
   dark) and diff against the `/styleguide` route's `visual-baselines`. An
   unintended visual change fails; an intended styleguide change re-baselines
   *explicitly* (a delta, never silent drift).

## Completion

- `coldpress visual-verify` exits 0 (no token violations).
- No unexpected visual-baseline diffs.
- The verdict records both, with the used-styles report attached.
