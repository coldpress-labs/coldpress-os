### 3. System Overview authoring

Prompt:

> **System Overview.** Based on PRD purpose, project_shape (`context.md`), and tech-stack:
>
> - **System Purpose:** 1 paragraph (what this system does)
> - **High-Level Diagram (Mermaid):** the system at a glance — major components + external systems
> - **Architectural Style:** monolith / modular-monolith / microservices / serverless / hybrid
> - **Style Rationale:** why this style fits project_shape + scale targets (from personas)
>
> *Tier-1 method: `brainstorming` (six_thinking_hats) for style-choice deliberation.*
> *Tier-1 method: `design_thinking` define stage for system-purpose framing.*

Halt for user input.

### 4. Advanced-elicitation on vague_architectural_pattern

If user describes architecture with patterns like "modular", "scalable", "event-driven", "decoupled" without specificity, invoke `advanced-elicitation` (method `concrete-references`) — drill via "show me a system that has the qualities you want; what's similar / different about ours?".

### 5. Component identification

Prompt:

> **Components.** Walk every PRD user-story; identify the components needed to fulfil it.
>
> For each component:
> - Name + 1-line responsibility
> - Owns which PRD user-stories
> - Realises which UX screens / flows
> - Front-end / back-end / data-layer / integration / infrastructure
> - Imports brand-tokens from `brand-guidelines-v{N}` if front-end-visible
> - Tech-stack-component-mapping (which framework / library family)
>
> *Tier-1 method: `brainstorming` (round_robin) for alternative component decompositions.*

### 6. Supersede-check on PRD-feature coverage

For each PRD user-story-ID: verify it's mapped to at least one component. Uncovered stories surface as design-deltas — wait, no, this is Phase 6, so they surface as architecture-deltas (forward-carry per SKILL.md). For now, surface as inline issue + add to `architecture_deltas:` queue (mechanism mostly deferred but recording the gap is cheap).

### 7. Write into draft

Append `## 1. Overview` (System Purpose, Diagram, Style + Rationale, Key Design Decisions table — empty initially) and `## 2. System Architecture` → `### Component Architecture` (one entry per component).
